# 演示视频录制脚本 · QuizMaster

> 目标长度 8–10 分钟。建议开启前置摄像头，按下面顺序一遍录完，中途不要切换窗口。
> 录制前必做：`uv run python scripts/init_db.py --reset` 重置数据库，保证演示数据干净。

---

## 0. 录制前检查（不录进视频）

```bash
cd quizmaster
uv sync
uv run python scripts/init_db.py --reset
uv run python run.py
```

- 浏览器开两个标签页：普通用户页、管理员页（或用一个窗口 + 隐身窗口）。
- 窗口设为 1440×900 或 1920×1080，缩放到 100%。
- 如需演示超时，临时在 `.env` 设 `TEST_TIME_LIMIT_SECONDS="15"` 并重启（**只在 development 生效**，README 已写清）。
- 准备好账号：**交付版不预置学生账号**，请先在登录页注册一个普通账号
  （建议用户名 `demo`），并提前答 2–3 局 —— 排行榜、等级、历史成绩才有真实数据可讲，
  且这些数据确实出自这个账号自己的作答。管理员用 `admin / QuizAdmin@2026`。
- **备一个「只有手机」的兜底**：`dist/QuizMaster_安卓版.apk`（0.49 MB，断网可用）与
  `dist/QuizMaster_在线知识竞答_预览版.html`（双击即开）不需要服务在跑，现场设备出问题时能顶上去。
- **先决定新手指引要不要入镜**：登录后首页会自动开场（约 30 秒，见 §1.1）。要留就别动它；
  不留就点一次「跳过」—— 已读记在账号上，之后不会再自动弹。想临时强制开场用 `?tour=1`，
  明确不要用 `?tour=0`。

## 1. 开场（约 40 秒）

**画面**：登录页（左栏手绘插画 · 阅览室的午后，右栏登录表单）。

**讲稿**：

> 这是我实现的综合实践项目第 17 题——在线知识竞答游戏，名字叫 QuizMaster，题材是南开大学校史。
> 技术栈是 Python：FastAPI 做接口，SQLAlchemy 操作 SQLite，页面用 Jinja2 服务端渲染。
> 系统有三个角色层次：未登录、普通用户、管理员；核心规则包括抽题、计时、判分、排行，全部由服务端决定。
> 下面按"管理员维护题库 → 用户完整答题 → 结果与数据闭环 → 异常处理 → RAG 增强解析"的顺序演示。

**新手指引（约 30 秒，接在开场之后）**

**画面**：登录后首页自动浮出「荷宝」导览卡，高亮框依次圈出开考表单 → 统计看板 → 等级卡 →
最近成绩 → 侧栏知识库入口，最后一句「就这些，去玩吧」。中途按一次 `Esc`（或点空白处）跳过，
再从中右上角账户菜单 →「新手指引」重开一次。

**讲稿**：

> 登录之后会自动出现这份新手指引，讲解的角色叫荷宝，是前几轮我自己画的。
> 它是可跳过的 —— 点「跳过」、按 Esc、点任意空白处都行；看过一次就不再自动出现，
> 想再看就从右上角账户菜单里重开。指引的文案和步骤存在服务端，前端只负责高亮和定位；
> 如果脚本没加载，它整块不出现，也不会留下一个点了没反应的按钮。

## 2. 管理员维护题库（约 2 分钟）

**操作**：用 `admin` 登录 → 左侧「题库管理」。

1. 展示统计卡：题目总数 80、启用/停用、题型分布、各分类题量。
2. 用关键词「校训」搜索，展示筛选生效；再按难度「困难」筛选；再按题型「填空题」筛选。
3. 点击「新增题目」，题型选「填空题」，填写题干、参考答案、关键字、标准解析、分类、难度，保存 → 列表出现新题、统计数字 +1。
4. 点击某题「编辑」，把难度从「简单」改成「中学」→（口误改为）「中等」，保存。
5. 点击「停用」→ 状态变为停用。

**讲稿要点**：

> 题库支持三种题型：单选、判断、填空。判断题用固定的「正确 / 错误」两项；填空题没有选项，靠关键字判分。
> 填空题的判分刻意宽松：只要答出任一关键字、没有污言秽语、不是明显离谱的输入就算对 —— 它考的是「有没有记住这个知识点」，不要求措辞和标准答案一字不差。
> 每题必须有标准解析，不能只有一个正确选项。
> 停用是软删除，题目不再参与抽题，但历史成绩不会受影响——因为会话保存的是创建那一刻的题目快照，这一点后面会验证。
> 另外管理员还有「资料库与 RAG」页，用于导入讲义，等讲到 RAG 时再回来。

## 3. 用户完整答题（约 3 分钟）

**操作**：切到 `test` 账号（或先登出再登录）。

1. 首页展示四张统计卡（累计测评次数、最高得分、平均正确率、当前排行名次）与研习等级进度条。
2. 选择「10 题 + 分类：人物与校友 + 不限难度」，右侧「可用题量」实时刷新。点击「开始挑战」。
3. 答题页：指一下右上角倒计时，说明这是服务端签发的截止时间，刷新或关掉页面都不会重置。
4. 逐题作答 10 题：故意答错 2–3 题。遇到判断题就选「正确 / 错误」，遇到填空题就在输入框里敲关键字（失焦或回车即保存）。指出右侧答题卡格子变蓝表示已作答，点击格子可以跳题。
5. 讲一句：每选一次、每填一题都会立即保存到服务端，不是提交时才上传。
6. 点击「提交并结算」→ 确认弹窗提示未答题按错误计分 → 提交。

**讲稿要点**：

> 答题阶段前端拿不到标准答案，接口返回里根本没有这个字段；填空题连判分关键字都不会下发。
> 三种题型混在同一局里出现：单选和判断按键位判，填空按关键字判。超时的话，服务端会按已保存的答案自动结算，未作答按错误处理。

## 4. 结果与数据闭环（约 2 分钟）

**画面**：结果页。

1. 指分数环与评级（卓越 / 优秀 / 合格 / 待提升）。
2. 指那行**算式**：`正确率口径：8 × 100 ÷ 10 = 80` —— 强调现场可以用纸笔验算。
3. 指「本局研习积分 SP」，说明奖励的边界。
4. 向下滚动到逐题明细：答对的绿色左边框、答错的红色左边框，展开一题展示选项标注、你的作答与题库标准解析、来源资料与章节；再展开一道填空题，展示「你的作答 / 参考答案 / 判分要点」与命中的关键字。
5. 回到首页，展示统计卡与等级进度条已更新；打开「历史成绩」，展示刚完成的这局（状态、得分、正确率、用时、评级、SP）。
6. 打开「排行榜」，找到自己的名次；说明排序规则：最佳分数 → 平均正确率 → 最佳用时，**用时不计入分数**。
7. 打开「成就荣誉墙」：展示已解锁（金色）与未解锁（置灰 + 进度），并朗读 SP 公式。

**讲稿要点**：

> 评分口径记录在每一局里，叫 rule_version，默认是 A-1 正确率口径；同时保存了逐题拆解，所以历史成绩可复核、可审计。
> 奖励是旁路：它只读终态会话，失败也不影响成绩落库，而且可以用一条命令重算，结果和在线值一致。

## 5. 异常处理（约 1 分钟）

按顺序演示，节奏稍快：

1. **未登录访问**：打开隐身窗口访问 `/dashboard` → 自动跳转登录页。
2. **密码错误**：输入错误密码 → 提示「用户名或密码不正确」（不区分用户是否存在）。
3. **越权访问**：用另一个账号直接打开 `test` 的 `result` 链接 → 403 无权访问。
4. **题量不足**：选「20 题 + 分类：校园与文化」（该分类只有 10 题）→ 提示「当前条件下仅有 10 道可用题目」，创建失败，**不会生成缩水的一局**。
5. **超时**（如已设短时限）：开一局不作答，等倒计时归零 → 自动提交并标记为「超时自动提交」，得分按已保存答案计算。

**讲稿要点**：

> 这些都是自动化测试覆盖的用例，包括幂等——重复点提交不会重复计分。

## 6. RAG 与降级（约 1 分钟）

1. 回到结果页某道**答错**的题，点击「生成资料增强解析」。
2. 展示：加载态文案「正在检索课程资料并生成解释」→ 出现解释正文 + 「来源 1：《南开校史讲义》· 第一章 创校与早期发展」。
3. 再点一次同一题，指出「命中缓存」——不会重复调用模型，答案也不会漂移。
4. 切到管理员「资料库与 RAG」页，展示：功能开关、模型配置、资料份数与切片数，以及**降级策略对照表**。

**讲稿要点**：

> 检索是 BM25 稀疏检索，中文按单字和相邻双字切分，不需要向量库。
> 模型只能依据我提供的资料片段和题库标准答案解释，不能改答案、不能编造来源；返回的引用 ID 必须来自本次检索到的片段，否则整条结果会被丢弃并降级。
> 断网、Key 失效、超时、资料不足、输出不合规——任何一种情况都只影响这一块增强解析，**不影响成绩、历史和排行**。

## 7. AI 辅助开发（约 1 分钟）

**画面**：打开 `docs/AI_ASSISTED_DEVELOPMENT.md`。

**讲稿要点**：

> 开发全程用 AI 辅助，但我保留了完整的决策与复核记录。
> 比如技术栈：AI 原方案是 Next.js + TypeScript，我改成了 Python；
> 80 道题的史实与标准答案由我人工复核，这是不能外包的部分；
> AI 自查阶段发现并修复了 6 个缺陷，例如 Starlette 新版模板签名变化导致全站 500、Jinja2 中 `data.items` 命中 dict 内置方法导致列表页 500，这些都记录在案。
> 验证方式是跑测试：104 项 pytest 全绿，87 项 HTTP 冒烟测试全绿，其中包含真实调用模型验证 RAG；
> 新手指引另有一个 51 项的浏览器行为探针（高亮对齐、三条跳过路径、已读持久化）。

## 附：常见问题应答（答辩备用）

| 提问 | 回答要点 |
|---|---|
| 分数能否被前端篡改？ | 不能。分数由服务端按题目快照计算，客户端传的分数字段被忽略；标准答案在终态前不下发（有测试）。 |
| 为什么不做难度加权？ | 加权口径已登记在 `score_rules`（B-1）但默认关闭，因为它会破坏"分数 = 正确率"的可解释性；启用需新开会话指向新版本，历史不受影响。 |
| 奖励会不会影响排名？ | 不会。奖励只读终态会话，不参与任何排序；失败也不阻断成绩。 |
| RAG 会不会改答案？ | 不会。System 约束 + 服务端校验输出 JSON + 引用必须在本次 Top-3 内，否则丢弃整条结果。 |
| 题库被改后历史成绩会变吗？ | 不会。会话保存题目与标准答案快照，有专门测试覆盖。 |
| 超时怎么判？ | 服务端时间为准，超过截止即惰性结算为 TIMEOUT，按已保存答案判分，不额外扣分。 |
| 重复提交会怎样？ | 幂等，返回原结果，不重复计分、不重复加 SP。 |
| 现场没电脑 / 只有手机能演示吗？ | 能。`dist/QuizMaster_安卓版.apk`（0.49 MB，**零权限、断网可跑**）与单文件预览页都不依赖服务与网络，安卓 5.0 以上侧载即可。内核与网页版是同一份页面（脚本比对 sha256），题目取自真实服务、判分口径与 `scoring.py` 逐条对齐。 |
| 有小程序或 App 吗？ | 安卓 App 有（APK）。**小程序没做**：本机没有微信开发者工具、也没有小程序 AppID，做出来既编译不了也真机预览不了；同一份单文件页面可以直接作为小程序 `web-view` 的内容来源，所以缺口在环境而不在内容。 |
| 新手指引能跳过去吗？ | 能，四条路径等价：点「跳过」、按 `Esc`、点遮罩空白处、走完最后一步点「完成」。焦点锁在卡片内，关闭后交还；不想再看到就跳过一次（已读记在账号上）。 |
