# QuizMaster · 南开校史在线知识竞答系统

> 综合实践项目第 17 题「在线知识竞答游戏」的完整实现。
> Python 全栈单体应用：题库管理 → 随机抽题 → 服务端计时 → 服务端判分 → 成绩统计 → 排行榜 → 得分奖励 → 资料增强解析（轻量 RAG）。

**一句话简介**：一个以「南开大学校史」为题材的在线知识竞答系统，用户登录后随机抽题作答，成绩、统计与排行完全由服务端计算，并附带可核验的得分口径、研习积分等级体系与基于课程讲义的 AI 增强解析。

## 2. 对应选题与项目目标

- **选题**：第 17 题「在线知识竞答游戏」。
- **题材**：南开大学校史（创校与发展、人物与校友、校园与文化、精神与学科）。

**选题背景**：知识竞答把题库、随机出题、计时、判分和排行榜结合了起来 —— 既有完整的交互流程，又天然适合现场验证（抽到哪几道题、算出多少分、写了哪几条记录，都能当场对上）。题面要求交付一个**可完整玩一局**的竞答应用，本项目按这个尺度落地。

**项目目标**：完成题库管理、游戏开始、连续答题、计时计分和结果统计。

**在此之上自己加码的三条**：

1. 完成「题库 → 抽题 → 答题 → 判分 → 统计 → 排行」的完整闭环，且数据可持久化、重启可查询；
2. 核心规则（抽题、计时、判分、排行）全部由服务端决定，客户端无法伪造分数；
3. 在闭环稳定之上，叠加两个增强：**得分奖励体系**（评级 / 研习积分 SP / 等级称号 / 成就）与**轻量 RAG**（依据课程讲义的答案增强解析，可溯源、可降级）。

### 2.2 对功能完成的印证（在线知识竞答游戏）

本项目跑的不是静态页面，也不是写死的演示数据 —— 抽到的题、判出的分、落下的成绩都出自真实数据库。任选一种方式即可当场印证：

1. **按现场手册走一遍**（`docs/TEST_REPORT.md` §6）：改题干后历史成绩纹丝不动、倒计时归零自动交卷、同一局重复提交不重复计分、题库不够时明确拒绝而不缩水成局；
2. **跑自动化测试**：`uv run python -m pytest -q`（104 项）、`uv run python scripts/smoke_test.py`（84 项真实 HTTP 流程，串起注册 → 开考 → 作答 → 提交 → 成绩）；
3. **直接查库**：一局答完，`sessions` / `answers` / `scores` 三张表同时留下记录，重启服务后仍能在「历史成绩」里查到。

第二部分「所有项目统一完成要求」的逐条对照见 `docs/TEST_REPORT.md` §5.1（启动无阻断 / 非静态演示 / 关键规则可现场验证 / 数据完整闭环 / 异常处理 / README 与演示视频）。

## 3. 功能与角色

### 3.1 普通用户 STUDENT

- 注册 / 登录 / 登出（HttpOnly Cookie 会话）。
- 按分类与难度筛选，选择 5 / 10 / 20 题开始一局。
- 支持三种题型：**单选题**（A–D 四选一）、**判断题**（正确 / 错误）、**填空题**（自由输入，按关键字判分）。
- 答题页逐题作答，选择即自动保存到服务端；填空题失焦或回车即保存；服务端倒计时归零自动提交。
- 结果页查看得分、评级、正确率、用时、逐题解析与**可核验的算式**；填空题会展示你的作答、参考答案与命中的关键字。
- 历史成绩列表（按状态筛选、分页）与单局详情回溯。
- 排行榜查看自己的名次。
- 成就荣誉墙查看研习积分、等级称号、连续研习与成就进度。
- **知识库**：把题库背后的校史知识展开成一座可以逛的展馆 —— 校史时间轴、人物档案（米黄档案袋式翻转卡）、文化标识、易混淆辨析，以及把 80 道题当作可翻面记忆卡自测（支持按主题切换、随机洗牌、全部翻面）。
- 对已结束的会话，对任意题目生成**资料增强解析**（显示来源资料与章节）。

### 3.2 管理员 ADMIN

- 题库管理：分页 / 关键词 / 分类 / 难度 / **题型**筛选，新增、编辑、启停（软删除）。
- 题库统计：总量、启用与停用数、**题型分布**、分类分布、难度分布。
- 资料库管理：导入 `.md` / `.txt` 讲义并建索引，查看切片数，删除资料。
- 奖励重算：按原始终态会话重算所有用户的 SP、连续研习天数与成就（可审计）。

### 3.4 知识库

`/knowledge` 把「题库」「课程讲义」「校史事实」三样东西织在一起，让知识点可以被浏览而不是只能被考。页面自上而下分五段（前面是校史导语，不是数据面板）；左侧栏在本页会多出一组**章节目录**，其余页面不出现，点标题即跳到对应段落：

| 段落 | 形式 | 交互 |
|---|---|---|
| 导语 | 校史开场文字 + 纸标签图注 | — |
| 01 校史时间轴 | 1904 → 2019 共 12 个节点，按时期着色（赭石 / 朱红 / 银杏金 / 靛蓝 / 青绿） | 滚动时赭色轴线随阅读进度生长；节点可展开细节与出处 |
| 02 人物档案 | 严修、张伯苓、张彭春、周恩来、陈省身、曹禺、杨石先、姜立夫 | 米黄档案袋式卡片（标签页 / 装订孔 / 字段区），8 张等高；点击 3D 翻面看生平与出处，档案较长的几张背面可滚动 |
| 03 文化标识 | 校训、校歌、校名由来、校徽、校钟铭文、校区、标志建筑 | 印章式卡片，悬停点亮描边 |
| 04 易混淆辨析 | 校训 / 年份 / 校名三组对照，南开项金色高亮 | 行悬停展开缩进 |
| 05 知识卡片 | 80 道题按四个主题分组，正面给线索、背面给答案与出处（单选题给选项、判断题给正误、填空题给参考答案与判分关键字） | 图形卡翻面、主题切换、随机洗牌、全部翻面、翻面进度提示 |

两点设计取舍：

1. **内容全部服务端渲染直出**。JS 失效时五段内容依然完整可读，翻卡与筛选只是增强（翻转卡另有 `<noscript>` 兜底：正反面改为顺序堆叠，不翻转但内容完整）；`?reveal=1` 还能切换到**放映模式**：卡片全部以「已翻开」状态渲染，同时跳过入场动效，教师投屏时不用滚动就能一屏读完。
2. **知识来自哪里可追溯**。时间轴、人物、文化标识、辨析四段整理自 `data/seed/knowledge.json`（与题库标准答案同源的课程讲义），每条都标注出处；80 张题卡则由数据库实时派生，题库改题后知识库自动跟随。

### 3.5 交互与动效

动效全部是渐进增强，只动 `transform` / `opacity`，且整套在 `prefers-reduced-motion` 下退化为即时状态。

| 场景 | 效果 |
|---|---|
| 全站滚动 | 区块与卡片随滚动逐级淡入上浮（`--i` 控制错峰节奏） |
| 侧边导航 | 激活项左侧金色指示条生长 |
| 按钮 | 悬停微抬、按下回弹、点击波纹 |
| 知识库时间轴 | 赭色轴线随阅读进度生长（底层另有一条常显的浅轴线，保证「这是一条轴」先立住） |
| 知识库翻卡 | 640ms 3D 翻转，配合缓动曲线（`ease-out-expo`），支持键盘 Enter / 空格 |
| 结果页 | 得分环从 0° 转到实际角度；新解锁成就卡弹入；得分 ≥85 或解锁成就时撒庆祝粒子 |
| 进度条 | 等级 / 成就进度条从 0 涨到目标宽度 |
| 提示条 | 进出都带位移淡入淡出 |
| 键盘操作 | 选项/导航/进度格的焦点环只在键盘导航时出现（`:focus-visible`） |
| 答题快捷键 | 按键即时选中并保存，键帽式提示卡常驻右栏 |

补充两条与"可靠性"有关的实现说明：

- **滚动揭示不用 `IntersectionObserver`。** 它在 headless 浏览器与部分嵌入式 WebView 里不触发回调，会让内容永远停在透明态。改为 `scroll` + 时间戳节流 + 同步 `getBoundingClientRect`，并在 `load` / `hashchange` 与启动后几个时间点补检一次 —— 因为浏览器把视口定位到 URL 锚点（如 `/knowledge#people`）或恢复上次滚动位置时**不会派发 `scroll` 事件**，只查一次会让该区块保持不可见。
- **降级路径只有一条。** `放映模式`（`body.is-present`）、`prefers-reduced-motion`、JS 未注入 `html.anim` 三种情况共用同一个 `NO_MOTION` 开关：内容直接可见、数字直接写终值、动画全部跳过。CSS 层另有一份 `body.is-present .reveal` 兜底，即使脚本没跑起来也不会留白。

### 3.6 键盘与可访问性

| 项目 | 做法 |
|---|---|
| 焦点可见 | 全站 `*:focus-visible { outline: 2px solid var(--gold) }`。用 `:focus-visible` 而非 `:focus`，鼠标点击不留焦点框，键盘导航才显示 —— 这是原生语义，不需要 JS 判断输入方式 |
| 答题快捷键 | `A`–`D` 或 `1`–`4` 选中选项、`←` / `→` 切换题目、`Enter` 进入下一题；光标在输入框内时自动让位（填空题里敲字不会触发选项快捷键） |
| 键盘可达 | 翻卡卡片可聚焦，`Enter` / `空格` 翻面；选项与进度格都是原生 `<button>` |
| 屏幕阅读器 | 切题经 `.sr-only` 的 `aria-live="polite"` 播报「第 N 题，共 M 题」；选项用 `aria-pressed` 承载选中态；进度格 `aria-label` 说明「已作答 / 未作答 / 当前题」 |
| 表单语义 | 登录页用 `<h1>` 作页面主标题，错误提示 `role="alert"`，出错时不抢焦点（抢焦点会打断正在输入的键盘用户） |
| 减少动态效果 | 系统开启「减少动态效果」时不注入 `html.anim`，全部动画退化为即时状态（详见 3.5） |

两条实现取舍：

- **数字键按「选项顺序」映射，不硬编码 A/B/C/D。** 题库的选项键由服务端决定，写死字母会在选项集变化时静默失效。
- **焦点在按钮上时，`Enter` 交给元素自身的 `click`。** 否则「激活按钮」与「跳下一题」会各触发一次，表现为一次按键跳两题。

知识库还有一处面向"投屏"的取向：`?reveal=1` 放映模式让卡片全部以已翻开状态渲染并跳过入场动效，教师现场不必滚动、不必逐张点开。它同时被截图脚本复用为"一次成型"的渲染基线。

### 3.7 新手指引（荷宝导览）

登录后首次进首页会自动出现一份分步指引：一个叫**荷宝**的纸感水彩小形象站在左边，
右边一步一句地讲解「去哪开一局、成绩在哪看、校史去哪查」，同时用高亮框圈出当前说的
那块界面。

| 你可能关心 | 答案 |
|---|---|
| 嫌它烦怎么办 | **三条跳过路径**：点「跳过」、按 `Esc`、点任意空白处，等价 |
| 关掉之后还能找回来吗 | 能。顶栏账户菜单 →「新手指引」，随时重开（看过一次就不会再自动出现） |
| 它会不会挡着操作 | 不会。高亮区是透明的，卡片会自己躲开目标；窄屏上贴底变成抽屉 |
| 键盘能用吗 | 能。焦点锁在指引卡内 `Tab` 循环，`Esc` 关闭后焦点交还触发处 |
| 关掉脚本会怎样 | 指引整块不出现，也不会留下点了没反应的按钮（渐进增强） |
| 在别的页面打开是什么样 | 步骤**跟着页面走**：首页 8 步，知识库页 5 步 —— 只讲这一页能做的事 |

两处实现口径值得说明：

- **文案与步骤在服务端**（`app/services/tour.py`），前端只做高亮与定位 —— 同一句话不会
  在 Python 与 JS 里各存一份。是否看过记在账号上（`users.tour_seen`），换浏览器不会再被拦一次。
- **荷宝是本项目自绘的**。原型为南开大学官微学生团队原创 IP「紫菡」（昵称「荷宝」，
  2024 年建校 105 周年上线），本项目另绘了一版用于功能导览，出处见 §17。

设计细节与取舍见 `docs/DESIGN.md` §17。

## 4. 技术栈

| 层 | 选择 | 用途 |
|---|---|---|
| 语言 | Python 3.11+ | 后端与业务逻辑 |
| Web 框架 | FastAPI | 路由、依赖注入、异常处理 |
| ASGI 服务器 | Uvicorn | 本地运行 |
| 模板引擎 | Jinja2 | 服务端渲染页面 |
| ORM | SQLAlchemy 2.0 | 数据模型与事务 |
| 数据库 | SQLite（WAL） | 零服务依赖、本地持久化 |
| 校验 | Pydantic v2 | 请求体校验与枚举约束 |

## 11. 关键业务规则

### 11.1 会话状态机

```
IN_PROGRESS --主动提交--> COMPLETED
IN_PROGRESS --到期------> TIMEOUT（惰性结算：任意访问触发）
终态 --再次提交--> 返回原结果（幂等，不重复计分）
```

### 11.2 得分口径（默认口径 A）

```
score = round(correct_count × 100 / question_count)
```

- 未作答按错误处理：计入分母，不计入分子。
- **用时不计入分数**，只用于展示、SPEED 成就判定与排行榜第 3 排序键。
- 超时提交按已保存答案判分，**不额外扣分**。
- 每局保存 `rule_version`（默认 `A-1`）与逐题 `score_breakdown_json`，历史成绩不会因规则调整而漂移。
- 备选口径 B（难度加权 EASY 1 / MEDIUM 1.5 / HARD 2）已在 `score_rules` 表中登记但**默认关闭**，启用需新开会话指向该版本。

### 11.3 评级（仅用于展示，不参与排序）

| 评级 | 区间 | 文案 |
|---|---|---|
| EXCELLENT | 100 | 卓越 |
| GOOD | 85–99 | 优秀 |
| PASS | 60–84 | 合格 |
| NEEDS_WORK | 0–59 | 待提升 |

### 11.4 奖励机制（可完全关闭）

```
SP = 完成基数 20 + round(得分 × 0.5，上限 50) + 难度加成(EASY 0 / MEDIUM 5 / HARD 10) + 连续研习 min(5×(n−1), 25)
```

单局 SP 上限 105。等级由累计 SP 纯函数计算，不落库：

| 等级 | 累计 SP | 称号 |
|---|---|---:|
| L1 | 0–199 | 研习者 |
| L2 | 200–499 | 学者 |
| L3 | 500–999 | 研究员 |
| L4 | 1000–1999 | 资深研究员 |
| L5 | ≥2000 | 首席研习官 |

8 项成就：初见、明察秋毫、渐入佳境、登堂入室、倚马可待、凌绝顶、博采众长、日日新。

**奖励的边界（现场必须能讲清楚）**：

1. 奖励不改变分数、正确率与排行榜排序；
2. 奖励接口只接受会话 ID，其余从服务端数据推导，客户端**无法上报**分数或 SP；
3. 奖励结算在独立事务中执行，失败只降级为 `REWARD_UNAVAILABLE`，成绩与结果页照常；
4. `REWARD_ENABLED=false` 时隐藏入口，核心验收路径完全不受影响；
5. 管理员可一键重算，重算结果与在线值一致（可审计、可修复演示数据）。

### 11.5 防作弊底线

- 标准答案在会话终结前**绝不返回前端**（自动化测试有专门用例覆盖）。
- 分数由服务端按题目快照计算，客户端提交的任何分数字段都会被忽略。
- 排行榜只从终态会话聚合，不能由客户端上传。
- 每 30 秒与服务端校准一次时间，客户端时钟被篡改不影响倒计时权威。
- 会话归属校验：访问他人会话返回 403。

## 12. RAG 开启方式与降级说明

**开启**：在 `.env` 中设置 `RAG_ENABLED="true"`、`AI_BASE_URL`、`AI_API_KEY`、`AI_MODEL`，然后导入讲义（`data/corpus/*.md` 会在 `init_db.py` 时自动导入，也可在管理员页「资料库与 RAG」粘贴导入）。

**检索方式**：BM25 稀疏检索（中文按单字 + 相邻双字切分，英文按单词），叠加标题命中、分类匹配与短语命中加权，取 Top-3 切片；最高分低于阈值时明确返回「资料不足」。

**生成约束**：System 提示限定「只能依据提供片段与题库标准答案解释，不得改变标准答案、不得编造来源」；服务端校验输出 JSON，且**引用 chunkId 必须来自本次 Top-3**，否则丢弃结果并降级。成功结果按 `(session_question_id, user_answer)` 缓存，重复查看不再调用模型。

**降级矩阵**（全部不影响成绩）：

| 故障 | 处理 |
|---|---|
| `RAG_ENABLED=false` | 隐藏生成按钮，仅显示题库解析 |
| 未配置 API Key | 提示未配置，仅显示题库解析 |
| 未导入资料 | 返回「尚未导入任何课程资料」并降级 |
| 检索相关度过低 | 返回「检索相关度不足」并降级 |
| 模型超时（默认 8 秒） | 中止请求并降级 |
| 模型输出非 JSON | 校验失败并降级 |
| 引用不存在的片段 | 丢弃生成结果并降级 |

## 13.2 离线交付物（单文件页面 / 安卓 APK）的验证

这两份产物**不进 `dist/` 之外的任何地方**，也不是提交材料，但它们是「手里只有手机」时的演示入口，
所以同样按可断言的方式验过。生成与验证各一条命令：

```bash
# 生成：从正在运行的服务上取真实题目，产出单文件页面（同时更新 APK 的页内容）
UV_DEFAULT_INDEX=https://pypi.tuna.tsinghua.edu.cn/simple \
  uv run --with pillow python ../.workbuddy/tmp/build_preview.py

# 打 APK：aapt2 + javac + d8 + zipalign + apksigner，不依赖 Gradle
UV_DEFAULT_INDEX=https://pypi.tuna.tsinghua.edu.cn/simple \
  uv run --with pillow python ../.workbuddy/tmp/build_apk.py

# 验页面（29 项：自包含 / 指引 / 本地判分），默认验 dist 里那份
node ../.workbuddy/tmp/verify-preview.mjs

# 验「装到手机上的那份」：从 APK 里解出 assets/app.html，再跑同一套断言
node ../.workbuddy/tmp/verify-preview.mjs ../.workbuddy/tmp/apk-extracted.html
```

`build_apk.py` 自己也会自检并在任一项不符时报错退出：包名、可启动 Activity、`sdkVersion 21 → 34`、
**必须没有 `INTERNET` 权限**、v1/v2 签名均通过、包内 `assets/app.html` 与源文件 sha256 一致、
dex 里含有 `MainActivity`。

> 两点说明：APK 的 `assets/app.html` 与 `dist/` 里那份单文件页面**字节完全相同**（打包时会比对
> sha256，不一致就报错），所以「验了产物就等于验了 APK 内核」不是一个说法而是被脚本守着的事实；
> `verify-preview.mjs` 的命令行参数必须是**绝对路径**，传相对路径会拼出非法的 `file:///…` URL，
> 页面加载不出来、断言全红，看起来像页面坏了。

## 15. 已知限制

1. 支持单选 / 判断 / 填空三种题型。**填空题判分刻意宽松**：只要命中任一关键字、不含污言秽语、且不属于「明显离谱」的输入（超长粘贴、单字重复灌水、无任何可识别字符），即判为正确 —— 它衡量的是「有没有记住这个知识点」，不做措辞比对，也无法判断表述上的细微语义差异。参考答案仅作归一化后的兜底。
2. 排行榜采用内存聚合，用户规模在万级以内性能充裕；更大规模需改为 SQL 聚合。
3. 题库 80 道的**标准答案与填空题关键字需人工复核**后定稿（校史史实类题目尤其需要）。
4. 未做实时多人竞赛、积分商城、抽奖等（明确为非目标）。
5. 会话倒计时以服务端时间为准，但网络往返会带来 1 秒内的显示误差。
6. RAG 检索为稀疏检索，不做语义向量召回；若需要更强召回可替换 `app/rag/retriever.py`。

### 15.1 未来修改方向

- **增加闯关系统**：把现在「自选题量、随机抽一局」的形态扩展为分章节、分难度的关卡链路 —— 逐关解锁、连对加成、每关独立结算。数据模型上只需在 `sessions` 之上叠一层闯关进度，现有判分与快照逻辑可原样复用。
- **UI 界面优化**：结果页的逐题回放与知识库的长文阅读仍有提升空间（错题对比视图、正确率走势图这类可视化），移动端窄屏的信息密度也可再压一档。
- **强化奖励机制**：现有 SP / 等级 / 成就只「累积」不「消耗」，后续可加入连续打卡、日榜 / 周榜与成就组合，让奖励不只反映历史总量，也能反映近期活跃度。

### 17.1 新手指引的虚拟形象（荷宝）

界面上的导览角色叫**荷宝**，是本项目**为自己这一版另绘**的内联 SVG（`app/templates/_mascot.html`），
不是任何官方素材的描摹或矢量化，也不含位图。

原型是**南开大学官微学生团队自主设计**的原创 IP：大名「紫菡」（南开紫的「紫」+ 红菏菡萏的「菡」），
昵称「荷宝」，2024 年建校 105 周年随官方表情包上线（澎湃新闻《气氛组就位！「荷宝」上线为南开庆生》，
2024-10-16）。**原型著作权归南开大学原作者**，本项目仅作非商业的课程作业用途，并在指引卡底部与本文中署名。

自绘版与官方原型的区别（避免混淆）：头饰改为「未开的荷花苞 + 两片不对称侧叶」、颈间加荷叶圆领、
胸前纹样换成与本站品牌徽记同源的**银杏叶**、配色取自本站纸感水彩调色板、姿势为导览动作。
它**背景透明**（SVG 里没有任何铺满画布的底色矩形，测试有断言守着），也不新增任何静态图片文件。

若要换成自己设计的角色：替换 `_mascot.html` 里的宏即可（保持 `mascot-svg` 类名与 `data-pose` 四种姿势），
模板与样式无需改动。

### 17.2 六张手绘插画

界面上的六张图片都是**手绘水彩风格的插画**，不是校园实景照片：

| 文件 | 用途 | 内容 |
|---|---|---|
| `hero-campus.webp` | 首页横幅轮播 · 第 1 帧 | 校园主楼与钟楼，绿树与晨光 |
| `hero-xinkaihu.webp` | 首页横幅轮播 · 第 2 帧 | 八里台校区新开湖，湖面倒映着教学楼 |
| `hero-muzhai.webp` | 首页横幅轮播 · 第 3 帧 | 津南校区木斋图书馆，红砖楼体与穹顶 |
| `hero-jinnan.webp` | 首页横幅轮播 · 第 4 帧 | 津南校区大通学生活动中心，白色镂空立面与湖畔垂柳 |
| `hero-library.webp` | 登录页左栏 | 图书馆阅览室一角：拱窗、书墙与绿色台灯 |
| `hero-desk.webp` | 结果页横幅（右栏） | 摊开的笔记本、钢笔与一小圈桂冠 |

六张图由图像生成模型按同一套提示词产出，**刻意保持风格统一**：手绘水彩 + 墨线勾边 + 可见纸纹。
选择插画而不是实景照片，有两个理由：

1. **版权干净。** 实景照片无论从哪来，都要逐一确认授权与是否带水印。上一版用的两张校园照片
   检索自公开网络，其中一张带第三方媒体水印，需要另行裁切处理（复盘见 `docs/DESIGN.md`）。
2. **风格可控。** 六张图要落在同一个视觉世界里，用同一组提示词生成，比到处找图再调和更稳。

首页横幅是轮播：四帧按 6.2s 自动切换，鼠标悬停或切到后台标签页时暂停，右下角圆点可直接跳到某一帧。
脚本失效时只有第一帧可见（`opacity` 由 CSS 控制），所以**关掉 JS 也能看到一张完整插画**，不会是一片空白。

**水印处理。** 生成平台会在图片右下角叠加「AI 生成 / 平台名」水印（实测位于原图 1536×1024 的
y≈964–1020 一带）。六张图统一从原图裁到 y=950 —— **交付物中不含任何水印**。
裁切位置由像素统计确定，不靠目视估算；`scripts/smoke_test.py` 里有断言钉住成图尺寸，
尺寸一旦变化就说明有人放回了未裁切的原图。

**画幅按槽位定，不搞一刀切。** 六张图分两种画幅，各自对齐它实际所在的展示框：

| 槽位 | 交付画幅 | 张数 | 尺寸 | 为什么 |
|---|---|---|---|---|
| 首页横幅轮播 | 2.25:1 | 4 | 1152×512 | 首页插画框实测 565×252 = 2.246:1，画幅对齐后 `object-fit: cover` 裁不动它 |
| 登录页 / 结果页 | 1.616:1 | 2 | 960×594 | 槽位是 1.87:1 的竖幅，只裁约 14%，且两图都是满幅纹理，不伤构图 |

这不是一开始就想清楚的：早先六张统一做 960×594，结果首页那个 2.25:1 的框只能显示到图片高度的 **72%**，
新开湖那一帧的湖面正好落在被裁掉的下缘里 —— 整条湖看不见。靠 `object-position` 挪焦点只能遮丑，
**把交付图重构成槽位的形状才是根治**。四帧的裁切带按内容人工选定（主楼保钟楼塔尖、木斋保穹顶、
大通保垂柳与倒影、新开湖保整条湖与石岸），不居中一刀切。复盘见 `docs/DESIGN.md` §5.6。

**为什么是 WebP。** 同一批插画若按旧方案存成 1200 宽的 JPG 要 1255KB；改成 WebP（quality 76，
method 6）后六张合计 **642KB**，单张均重 107KB。首页首屏要一次挂上四帧轮播，这个差别直接落在首屏时间上。
1152 宽对应首页右栏约 565 CSS px 的展示宽度，150% 系统缩放下仍然不糊。

**许可。** 插画由项目作者通过生成模型产出并直接使用，不涉及第三方著作权。
若要换成自有素材（实拍照片或手绘均可），**按同名放入 `app/static/img/` 即可**，模板与样式无需改动；
只需同步更新 `scripts/smoke_test.py` 里的尺寸与体积断言（注意首页四帧要保持同一画幅）。

未裁切的生成原图、逐帧构图脚本与 JPG 母版存放在开发期的临时目录 `.workbuddy/tmp/` 下
（`handdrawn/`、`herogen/`、`render_hero_v4.py`、`quizmaster-jpg-masters/`），**不随交付**。
